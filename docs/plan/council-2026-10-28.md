# Quad-council verdict on SPEC-v1 (run 20261028-114313-6f18, 4 of 4 seats, standard depth, 343 s)

Chairman synthesis written before opening the seat key.

## Agreement (all four seats)
- **Verdict: ship with changes; the architecture holds** (adapter contract, SARIF ledger, sourced corpus, broken/fixed fixtures). No seat asked for a redesign. Confidence 78–95.
- **Reachable must not click for real.** A real click on Send submits, navigates and corrupts the preservation checks that follow; a no-op handler would also let a dead Send pass. Use hit-testing (centre + four inset points) and Playwright's `click({ trial: true })`; make task completion an explicit `operate:` step with a declared observable outcome.
- **State preservation is per-field policy, not equality.** Reflow legitimately changes `scrollY` (research 03 saw 1500 → 1518 after rotate); media must advance; autosave legitimately writes storage. Exact equality for form/focus/selection; anchor-based scroll with tolerance; media progression ≥ 0; storage/history = no loss on declared keys, additions allowed.
- **Acceptance 11.4 was wrong.** Demanding two segments after every fold rejects a valid unfold-to-flat (one segment) and accepts the wrong hinge. Self-check compares expected vs observed (viewport, DPR, CSS posture, segment rects) after every configuration change; the posture→segments expectation lives in the profile.
- **Keyboard: `env(keyboard-inset-*)` cannot be injected by a stylesheet.** Drop `inset`. Implement `resizes-content` (shrink) and an opaque fixed overlay with hit-test for the Chrome-Android/iOS default (`resizes-visual`), labelled `keyboard-overlay-approx`. Fixture 3 as written could not fail (a fixed footer rides above a shrunken layout viewport).
- **Sampling at 50 ms is not an oracle.** Install observers before the trigger via `addInitScript` (MutationObserver + per-frame log), decide at quiescence (quiet frames + cap), treat a transient loss as `review`.
- **Demote generic geometry.** Pairwise overlap (ReFLAIR measured ReDeCheck collision at 7.29 % precision), per-element overflow and whole-page element-loss produce false fails on correct responsive pages (nav → hamburger). Overlap/clipping fold into the hit-test; overflow and target-size are opt-in diagnostics; element-loss is scoped to declared controls + landmarks.
- **DSL needs**: a version key, ordered `steps` with per-step asserts (round trips cause the documented bugs), startup-only scenarios, `operate` + outcome, role+name locators, tolerances, `transient`, readiness, plural `profiles`, and no `input-change` until it has a driver and a rule.
- **Profile schema**: browser capabilities per engine/version (generated from BCD), not per handset; never write `measured` for a value nobody measured (keyboard heights); partial profiles are valid inventory but not executable; pin upstream registry revisions.
- **Evidence**: coverage manifest resolved before execution; unsupported required checks are inconclusive (`open`), not `notApplicable`; define CLI exit codes; fix SARIF shape (`logicalLocations` inside `locations[]`, `physicalLocation` → scenario YAML line, `level: none` for non-fail); record app build, scenario hash, oracle version; mask storage/form values in exported evidence.
- **Distribution**: `npx skills add` copies only `skills/foldproof/`; the launcher must resolve local bin → repo dist → `npx -y foldproof@<version>`; publish to npm at v0.1.0; CI checks skill version = package version.
- **Slice order**: vertical first (two hinge-bearing profiles, the unfold transition, three oracles, fixture 2, SARIF), corpus expansion in parallel.
- **Fixtures**: replace the generic fixed-width-toolbar fixture with an orientation-locked layout; add a round trip with delayed async work; add positive controls that must pass (legit nav collapse, autosave) to measure false alarms; cite the real issue each fixture reproduces.
- **Name**: keep foldproof; strike "prove"; tagline must say fold, rotate, resize, keyboard. **Single package**: keep; peer range `>=1.64 <2`.
- **Indispensable, not generic**: a Playwright-native API (`foldproof/playwright`: `attach`, `transition`, `assert`) that runs inside the user's authenticated suites, with YAML compiling to it; a zero-config `foldproof run <url>`; fixtures as a public benchmark; SARIF to GitHub code scanning via an Action.
